# QuickGrid in .NET 11 without URL-based sort and page state

Date: 2026-10-21. Based on the GitHub issues #66830, #69132, #69127 and #69129 (fetched and summarized) and on search results for community articles. Statements are "according to the source" and must be verified against the version in use (here 11.0.0-rc.2.26504.105).

## Build

The repository pins the .NET SDK in `global.json` (11.0.100 preview, `rollForward: latestFeature`, `allowPrerelease: true`). Install a .NET 11 SDK; in Visual Studio enable "Use previews of the .NET SDK".

```
dotnet build EBQuickGrid.sln
dotnet run --project EBQuickGrid.Server/EBQuickGrid.Server.csproj
```

The test page (`/`) shows `EBQuickGrid` with test data and a filter per column, rendered with `InteractiveAuto`. Start `EBQuickGrid.Server`.

| Project | Purpose |

## What changes

Starting with .NET 11, QuickGrid writes sorting and the current page into the URL (query parameters). Sortable column headers and the paginator are rendered as `<a href>` links instead of buttons. The goal is static SSR support (issue #66830).

## Drawbacks and compatibility

| Topic | Impact | Source |
|---|---|---|
| Headers and paginator are links instead of buttons | Selectors in UI tests and CSS that target `button` break | #69132, ABP article |
| Parameter names are inconsistent | Older docs: `sort`, `order`, `page`; current per #69127 and the ABP article: `sort`, `direction`, `page`. Names changed during the previews | Docs, #69127, ABP article |
| Docs possibly stale | Older docs and preview posts mention `QueryParameterNamePrefix` and `?order=`; per the ABP article this does not exist in RC1 (order is ignored) | ABP article |
| Several grids on one page | Default names collide; each grid needs its own names via `QueryParameterNameOptions` | #69129, QueryParameterNameOptions.cs |
| App-owned query parameters (`[SupplyParameterFromQuery]`) | Links generated by QuickGrid keep them; whether your own links keep the grid parameters is up to the app | ABP article |
| Compatibility switch | Restores only the button rendering, not the URL behavior (see next section) | #69132 |
| Every sort and page change alters the URL | Browser history fills up with entries; the URL no longer belongs to the page alone (conflicts with custom URL/history handling) | Inference from the design, not directly documented |

## The AppContext switch (most important point)

Name (confirmed in #66830 and #69132): `Microsoft.AspNetCore.Components.QuickGrid.EnableUrlBasedQuickGridNavigationAndSorting`

- `false` only restores the button markup (confirmed for SSR and Interactive Server).
- It does not disable reading and writing the URL state, according to the docs as read in #69132: QuickGrid still reads and writes the URL.
- There is also a project file variant (`RuntimeHostConfigurationOption`) that is not in the docs that were checked.
- Untested with trimming (the test in #69132 was inconclusive).
- Consequence: the switch alone does not keep the URL clean. That is why the `EBQuickGrid` library also replaces QuickGrid's NavigationManager with `SilentNavigationManager`, which never writes to the browser address bar.

## Most controversial places

There is hardly any real debate in the threads (#66830 has 3 comments, 2 of them from bots). The most critical points are in these issues:

| Issue | Topic |
|---|---|
| [#66830](https://github.com/dotnet/aspnetcore/issues/66830) | The proposal lists its own risks: buttons become links (CSS breaks), `Paginator` changes from `OnParametersSet` to `OnParametersSetAsync` (overrides in subclasses are silently no longer called), several grids share the default parameters, sorting by column title (renaming breaks bookmarks, columns without a title cannot be sorted via URL). API review (halter73) discussed the name `QueryParameterNamePrefix` and replaced it with `QueryParameterNameOptions`. |
| [#69132](https://github.com/dotnet/aspnetcore/issues/69132) | The change is not documented in the .NET 11 breaking changes (reference to #65023, undocumented QuickGrid rendering changes). The switch restores only the markup, not the URL behavior. On Interactive Server the URL now changes, and Back/Forward moves through grid states. `sort=name` does not work, `sort=Name` does (case sensitivity). |
| [#69129](https://github.com/dotnet/aspnetcore/issues/69129) | The docs named `QueryParameterNamePrefix`, the implementation uses `QueryParameterNameOptions`. Docs were corrected in AspNetCore.Docs PR #37632. |
| [#69127](https://github.com/dotnet/aspnetcore/issues/69127) | No problems reported. `sort` takes the column title, `direction` takes asc/desc. Interactive Auto and standalone WebAssembly were not tested (relevant for this sample, which uses Auto). |
